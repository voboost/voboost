# Product release tooling

This directory is the product-level release owner. It is a standalone flat Rust crate: `Cargo.toml` points the binary directly at `main.rs`, and the implementation modules remain beside it.

The product repository no longer contains a Gradle project or component source trees. App, agent, native, and installer builds belong to their sibling repositories and enter this crate only as exact release inputs. The root Node package remains a documented transitional dependency of product evidence and documentation tooling; this Rust crate neither invokes nor depends on it.

## Source definition

`release/version.toml` is the single editable **current release input** (authoring input). Every build run reads it once, validates it, and writes an immutable resolved snapshot named `<release>.toml` into the run's inputs directory (`build/<run>/inputs/`); all compose/restore/evidence consumers use those frozen bytes and their SHA-256. The Rust authority still enforces `filename == <release>.toml` for resolved definitions; the authoring input is validated through `Definition::load_authoring` which skips only the filename rule. Historical `<release>.toml` files under `release/` are immutable snapshots of past definitions.

`<release-id>.toml` contains one canonical product SemVer, the channel, an optional older `base_release`, full 40-character lowercase Git commits for every production repository, the exact Android `versionCode`, compatibility numbers, and required host, emulator, device, and vehicle gates. Unknown fields are rejected, including the obsolete manual `mode = "build"` and `mode = "reuse"` choices.

## TS build chain

- `tools/release/release-identity.ts` — reads `release/version.toml`, produces the immutable resolved `<release>.toml` snapshot and digest.
- `tools/release/build-closure.ts` — the full source build (machine profile): natives → app APK → agents → sign/compose/verify via this crate → profile marker checks → source snapshot before/after → receipt, published atomically with a complete marker. Never reads a retained base closure.
- `tools/release/installer-version.ts` — generates installer compile-time version inputs (`VOBOOST_PRODUCT_VERSION`, Tauri config override, frontend metadata) from the frozen resolved definition.
- Shared primitives: `tools/release/paths.ts` (durable output policy), `process.ts` (argv runner with redaction/timeout), `closure-steps.ts` (sign/verify orchestration, publication with single-writer reservation).

Local signing authority is an explicit external directory (mode 0700/0600), outside source repositories, and is never copied into outputs or inventories.

The hermetic suite is `cargo test --manifest-path release/Cargo.toml --locked` and contains no ignored tests. Real APK integration is an explicit required target: `ANDROID_SDK_ROOT=<sdk> cargo test --manifest-path release/Cargo.toml --locked --features android-integration verify::tests::pinned_android_tools_extract_identity_from_exact_signed_apk -- --exact`. It requires pinned Android build-tools `34.0.0` and `keytool`; missing inputs fail instead of skipping. Ordinary verification CI and the local beta1 constructor both invoke this gate explicitly.

`compose` does not trust APK evidence fields. It runs `aapt2` and `apksigner` only from the pinned Android SDK `build-tools/34.0.0` directory, bounds both tool outputs, requires a verified v2/v3 APK with one signer, extracts `packageName`, `versionCode`, and signer-certificate SHA-256 from the exact APK, and hashes the same file. Schema 1 accepts `versionCode` only in `1..=2100000000`, and the observed value must equal source-definition `android.versionCode`; beta1 pins `1000010`. `inspect-apk` may retain observed values as evidence output; when passed back to `compose`, every field must equal fresh extraction or authoring stops.

`verify-manifest` verifies an artifact-only directory and rejects the manifest pair as undeclared input. `verify-product-closure` verifies exactly the signed product directory: `voboost.json`, raw 64-byte `voboost.json.sig`, and every declared artifact. Beta1 therefore has 67 artifact files and 69 product-closure files. The product signature is verified before artifact identities; extra, missing, symlink, directory, and special entries are rejected.

`verify-apk-product-root` reads the same exact APK through a bounded ZIP parser, counts central-directory names independently of library lookup, requires exactly one compressed or stored `assets/config/release-public.pem`, parses only canonical Ed25519 SPKI PEM, and compares the extracted raw key to the source-pinned product root. Missing, duplicate, malformed, oversized, or substituted assets fail independently of APK certificate validation.

The command derives each component-artifact decision from final bytes. Equal name, size, SHA-256, and metadata reuse the previous identity. Different bytes at an unchanged owning repository commit stop the command as a reproducibility failure. No source definition contains a per-artifact build/reuse mode.

`restore.json` and `restore.json.sig` are product-derived recovery authorities. `produce-restore` binds canonical `releaseIdentity`, the SHA-256 of exact source-definition bytes, and the SHA-256 of canonical artifact rows excluding the restore pair, avoiding a cyclic digest. It signs exact document bytes with a raw Ed25519 restore-role key. `compose` requires the matching configured public key and rejects malformed, stale, or substituted recovery authority before authoring `voboost.json`. No production private key is stored in this repository.

Draft 2020-12 and semantic responsibilities are listed in [`SCHEMA-CONFORMANCE.md`](SCHEMA-CONFORMANCE.md).

`fixtures/wire/` is the closed product-owned cross-component corpus for operation completion, installed inspection, startup-mode confirmation, resident status, and external uninstall absence. `write-wire-fixtures` generates the seven strict typed schema-1 documents and their sorted `SHA256SUMS`; `verify-wire-fixtures` requires the exact generated bytes, hashes, names, and no extra entries. Component repositories consume these files or byte-identical copies pinned by the listed SHA-256, rather than maintaining independent examples.

After intentionally regenerating the authority corpus, run `sync-wire-fixtures.sh` to replace only the eight named files in both component mirrors. It never deletes an unexpected entry: such a mirror remains a hard failure that must be inspected. The read-only local release planner independently rechecks complete inventory and byte equality.

The CLI validates and authors local files only. It can apply a caller-provided raw Ed25519 key for isolated signing, but stores no private key and has no remote authority. It does not checkout repositories, invoke component builds, create Git tags, upload assets, publish a GitHub Release, or update a channel pointer.

## Beta1 orchestration

`1.0.0-beta1.toml` pins the current five component commits. `local-beta1-ci.sh <workspace-root> <output-plan.tsv>` is a read-only simulator: before recording any source or artifact evidence it requires exact eight-entry inventory and byte equality between the product wire corpus and both `voboost-inject` and `voboost-installer` mirrors. It then verifies each local HEAD, records the product and five component HEADs, computes each exact working-tree Git tree without changing the repository index, records the status digest, hashes every available known artifact, marks missing artifacts explicitly, and records source push, tag, GitHub Release, and channel update as blocked.

`init-local-test-authority.sh <new-authority-directory>` creates one persistent local test authority outside source, temporary, and build/cache trees. The new private mode-`0700` directory contains four distinct Ed25519 roles, a mode-`0600` Android JKS with a 365-day test certificate, and three signed public role fixtures. The command refuses an existing path and never overwrites an authority. Private material remains until the user explicitly removes it.

`build-emulator-beta1.sh <workspace-root> <authority-directory> <new-output-directory>` builds one signed AVD closure from current app, agents and production-path native sources. It requires a complete persistent local test authority and verifies the product signatures, embedded roots, absence of retired emulator markers, APK certificate embedded by Uninstall, production init, closed product inventory and unchanged source snapshot. Its evidence identifies `production-selinux` and sets production, vehicle and publication proof to false: an AVD run does not establish vehicle behavior. The script creates no platform package. Its intermediate state remains in the new sibling `<output>.work` directory after failure or success; only an output containing `output-identity.txt` is complete.

`run-emulator-beta1-gate.sh /absolute/path/to/config.json` runs the product-owned functional dispatcher with exactly twenty-seven case IDs. The closed data config contains `workspaceRoot`, `voyemuRoot`, `voyemuProfile`, `closure`, staged macOS package root `package`, immutable `dmg`, approved Voboost Fixture `fixture` (or explicit `null` when unavailable), and a new `output`. The profile must already be prepared and running under the operator's runtime lease. The runner never starts, stops, restarts or rebuilds it. With `nativeSession`, it uses the installed Voyemu native CLI through `test --root <voyemuRoot> --request <request.json>` and an explicit private ownership receipt, plus the verified packaged installer. The owner starts and stops the Android-only background session outside the runner. Native JSON operations provide current UI trees, fenced input, CAN and boot observations; captures are diagnostic unless the selected check explicitly requires visual evidence. The legacy prepared-profile adapter uses the checkout's `src/cli.ts`; it is a separate contract and is not a substitute for native-session evidence. It never invokes ADB directly, runs arbitrary shell/scripts, accepts coordinate presets or caller pass results, or interrupts installer children for fault cuts.

The same command now writes `output/report.md` after a terminal run, including failed and unavailable runs. The report lists all 27 cases and subchecks, recorded monotonic action times, boot IDs, evidence links and pending visual review. A nonzero gate exit is preserved; report failure or a zero exit without complete accepted evidence remains nonzero. `npm run --silent emulator:report -- /absolute/run/emulator-runtime-evidence.json` regenerates a report from retained evidence without a live VM or mounted package. Missing or changed evidence artifacts are rejected.

The runner freezes input digests, compares package Resources to the closure, checks the prepared `machines/<profile>/machine.json` inventory against its configuration, and rejects partial/duplicate/unexpected verify IDs, wrong expectations, missing actual fields and failed observations. The prepared inventory is profile-specific, not a hardcoded count. All original cases 1–17 remain mandatory. Execution order is `1,2,3,4,5,13,14,12,6,7,8,9,19,10,11,18,24,25,15,16,20,21,22,23,27,17,26`: vehicle persistence and launcher order precede locale traversal, extensions precede final Settings uninstall, and case26 aggregates afterward. Case12 explicitly enables its launcher agent prerequisite. Each boot has its own identity/verify/Enforcing/UI coverage. The emulator-only install flag prearms a transaction/manifest/attempt-bound first-boot barrier. The native installer waits before reboot two; the product gate completes its unchanged full first-boot verification and captures, then requires a same-boot waiting status and accepted consumption receipt. Failed or unavailable proof never accepts. Other inspect/snapshot/screenshot observations may observe an active writer without root provisioning or mutation. `boot-timings.jsonl` retains monotonic diagnostic event/check timing independently of semantic evidence. Missed/offline/crossed windows remain unavailable, never inferred from the final boot.

Schema3 `emulator-functional` receipts bind actions and artifacts to the kit/runtime/serial/boot/locale and require a separate preparation record. Legacy schema1 transaction receipts and schema2 functional receipts without preparation are not reinterpreted. Preparation invokes packaged CLI `--uninstall`, retains the exact complete nine-check receipt and package/runtime/boot, and records normal/already-absent/emergency explicitly. Any changed preparation boot gets full independent boot coverage; fresh absent status, Inspect, complete profile verification and UI capture must agree on its boot. Emergency cleanup satisfies only preparation, never cases2/3/17. Case1 checks clean status and installs. Case2 saves a strict normal receipt and verified new boot; case3 references that exact action receipt with fresh same-boot absence and full verification instead of another uninstall. Case24 retains this real initial absence proof separately from actual initial CAN and present false root readback.

Fresh package-aware semantic selectors reject stale or foreign nodes. Keyboard input requires a freshly focused exact-empty editor (or a proven legitimate clear), a live layout and real key nodes. Case12 asserts first-slot UI readback after drag and after reboot. Settings uninstall is preceded by the exact standalone observer armed event; ordinary stderr is retained separately. Normal removal rejects emergency fallback.

Missing authoritative CAN/catalog/locale/font/order observations, source-bound visual review, first-start cells and outage evidence produce named unavailable subchecks. Captured logs or screenshots alone do not establish complete agent behavior or review. Known manual receipts stay outside the executable runner inputs. Overall pass requires every required case/subcheck/boot to pass. Observation timeout never sends TERM/KILL: the unresolved child PID and retained lease are recorded and further mutations are forbidden. Failures retain packaged diagnostics, logs, inspect and official verify before any recovery; this runner performs no recovery. Host tests establish dispatcher/protocol boundaries only, not an Android, vehicle or public release result.

Fixed offline owning Gradle tests regenerate `voboost-agents/build/evidence/settings-copy.json` before runtime admission. Their before/after Git snapshots must match the closure parent's source-build `receipt.json`; actual JUnit reports and a host-only source-bound receipt are retained. The copy artifact commits every production Java/JSON input, exact metadata and delivered DEX. Language and uninstall checks consume the actual public-API captions. Ordinary bounded ZIP logs bind exact package/serial/context, and sequence windows require same-boot Inspect endpoints. Package classification uses fresh full scans with actual UID/flags, while OEM icon review remains separate.

The vehicle program uses semantic OEM Vehicle controls for disabled cold/warm baselines and armed cold/warm restoration, normal reboot and closed Sleep/Wake. Root diagnostics distinguish present booleans, absent and unavailable; warm restore additionally requires actual callback OFF/ON and fresh default-then-restored CAN reads. Initial clean nine-check absence, ordinary FEV-off/PW-on inputs and root seeding belong to the primary runtime; other initial inputs belong only to named host tests. Passive `ui-qinggan` composition and eight-target layout records support source/locale/measurement subchecks, while all required PNG review and unsupported production error/outage branches remain explicitly unavailable. The config accepts no commands or pass receipts.

`build-local-beta1.sh <workspace-root> <retained-authority-directory> <new-output-directory>` is the real local test constructor. It freezes source snapshots, validates and reuses the explicitly selected retained local authority, and reserves a new sibling `<output>.work` directory. Evidence authority is deliberately not created before the vehicle gate. App/inject receive only public roots. The current installer `build-macos-universal-app.sh` builds both slices inside the same session, and the eight-argument `build-mac-dmg` interface verifies a separate corresponding-source directory before packaging and uses installer-pinned universal ADB. The local output exports `corresponding-source.tar.gz`, `corresponding-source.json`, and `BUILD-MODIFIED.md` in `voboost-corresponding-source-<release>` beside the DMG. The DMG contains no source archives or source trees; readable licenses and notices remain in the application. Unrelated app/ADB inputs are forbidden. Shared path validation rejects existing paths and all source, temporary, build/cache, and symlink-alias paths. Source trees are checked again after final copy. Failure, signals, and success leave work, partial output, and the separately retained private authority intact for explicit inspection or continuation; the command never overwrites these paths. A successful output retains public identities and complete source/closure/package evidence, records that private keys persist in the explicit retained authority, and writes `output-identity.txt` only after the final source check. The integrated Android 9 app-daemon gateway has passed with a complete signed closure, so new local output is marked `ready-for-local-vehicle-gate`; the field authorizes that next gate only and does not claim a vehicle result.

The required order is local ephemeral build, local vehicle gate, verifiable uninstall/clean state, commit planning, commit/push source, exact-SHA CI, exact CI artifact download, clean CI vehicle gate with another uninstall/clean-state receipt, then a separate publication decision. Source push is not a release and is forbidden before the local vehicle sequence passes.

`.github/workflows/beta1-evidence-ingest.yml` is the sole trusted evidence producer. Its evidence public root comes from source-pinned `1.0.0-beta1-trust.json`, never a mutable variable. It accepts a canonical payload plus a raw Ed25519 user-machine signature, validates the exact product commit, workflow/trust/definition digests, component commit/tree pairs or downloaded CI artifact identities, and emits a provenance-bound Actions artifact. `local-delivery-evidence.schema.json` and `ci-vehicle-evidence.schema.json` define full canonical artifact rows and chained receipts; `tools/beta1-evidence.ts` recomputes artifact-set and receipt digests, ordering, nonces, and downloaded CI inventory.

`.github/workflows/beta1-ci.yml` defaults remote-source admission to false. Native preparation passes the Android certificate through Make `ANDROID_CERT_SHA256`. After protected signing and closure verification, secretless Windows and macOS jobs use exact installer/ADB source, protected fixture artifacts, product-owned embedded-root scans, and package reopen. The Linux job builds only `voboost-installer-cli` for `x86_64-unknown-linux-gnu` with `--no-default-features --features cli`, verifies ELF hardening and the absence of GUI/network-help dependencies, appends the exact signed 69-file closure to the same verified bytes, reopens it, and creates a one-entry mode-`0755` tar.bz2 without bundled ADB. The aggregate accepts only the exact EXE/DMG/tar.bz2 inventory. Trust remains unprovisioned and remotes disabled; the emulator gateway and vehicle gates remain separate blockers.

`.github/workflows/beta1-publication.yml` is only the separate manual decision after a clean CI vehicle gate. It re-downloads admitted artifacts, verifies their archive and canonical payload hashes plus closed inventory immediately before mutation, and contains no build or signing command. The authenticated API state machine resumes a matching draft or accepts an already public exact tag/title/prerelease/asset set after an ambiguous success; every difference fails without overwrite/delete. The separate channel job can accept only an already-published exact signed pointer and cannot create a new one until immutable hosting is configured. Publication remains disabled by default.


### Full 27 with manual visual review

The default shell runner does not supply a visual reviewer and therefore cannot claim full visual acceptance. Use the explicit local runner instead:

```sh
node tools/emulator/run-manual-review.ts /absolute/config.json /absolute/session-review.pub /absolute/release-authority-directory /absolute/new-review-receipt.json 3600000
```

Supply an independent session-only Ed25519 review key. This tool never generates keys. The authority directory must contain the actual release/catalog/native/restore public keys; matching signing identities are rejected. Do not reuse release keys for review. All working files belong inside the project.

Before final Settings uninstall the runner emits `manual-review-request-ready`, with the retained request path, and waits asynchronously for at most the supplied 1..7200000 milliseconds. Inspect every source-bound target and its actual captures. Create a separate JSON assessment document with exactly `reviewer: "root"` and `assessments`. Each target needs its exact `id` and `criteria`; each criterion needs exact request `id` and `expected`, a concrete `actual` observation, and explicit `verdict` (`passed` or `failed`). Missing observations and automatic success defaults are rejected. An observed defect must be marked failed.

After completing all observations, sign them in a separate terminal:

```sh
node tools/emulator/manual-review.ts /absolute/run/visual-review-request.json /absolute/completed-assessments.json /absolute/session-review.key /absolute/release-authority-directory /absolute/new-review-receipt.json
```

The existing gate verifies the signature, challenge, artifact hashes, runtime identity and complete criterion coverage. It then continues the remaining test actions and writes `report.md`. Timeout, invalid receipt, partial checks or functional failure never become a passing result. Keys for this review are separate from release trust and are not committed.

Case 12 requires Voboost Fixture initially absent. If a previous test installed `ru.voboost.tests.launcherfixture`, preserve its actual ownership evidence and explicitly remove that fixture with the existing installer `--emulator-check` action `remove-fixture` before starting the new run. Retain that preparation receipt and obtain a fresh `fixture-state`. Never fabricate an absent receipt or silently adopt a preexisting package as this run own fixture.
