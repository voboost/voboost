# Логи

[English](logs.md) | **Русский**

Логи Voboost помогают понять, почему не включилась функция, остановилось обновление или не запустился `voboost-daemon`. В beta1 их скачивают одним архивом через `voboost-installer`; вкладка Logs в составе beta1 не поставляется.

Voboost использует три уровня:

- `debug` — подробности проверок и решений
- `info` — успешные действия и изменения состояния
- `error` — ошибки, из-за которых действие не выполнено

## Вкладка Logs

Агент `logs` разрабатывается как вкладка Logs с записями из трёх источников: приложение Voboost, `voboost-daemon` и агенты, с фильтрами по источнику, агенту, уровню, времени и тексту. В beta1 этот агент не входит в состав поставки, поэтому вкладка в машине недоступна; статусы агентов перечислены в [таблице агентов](../docs-dev/agents-status.ru.md).

## Скачивание через установщик

Для скачивания логов включать агент `logs` необязательно. Подключите компьютер, запустите `voboost-installer`, выберите **Скачать логи** и укажите каталог.

Из командной строки укажите абсолютный путь к существующему каталогу; сам каталог не должен быть символической ссылкой. Каталог может содержать другие файлы:

```text
voboost-installer --logs <каталог>
```

После подключения установщик получает диагностические данные из машины и создаёт на компьютере архив `voboost-logs-<дата-UTC>-<время-UTC>-<случайный-токен>.tar.xz`. Архив сжимается системным XZ. Метка времени имеет вид `YYYY-MM-DD-HHMMSS`, случайный токен состоит из 32 строчных шестнадцатеричных символов. Отдельный архив в машине не создаётся.

## Что находится в архиве

- `manifest.json` — `schemaVersion: 1`, `format: "VBOOSTLOG1"`, заголовок с `schemaVersion`, `recordsLength` и `contextLength` и точные имена данных `records.jsonl` и `context.json`
- `records.jsonl` — сохранённые записи приложения, демона Android, агентов и приборки
- `context.json` — результаты сбора, журнал установщика и доступные сведения о состоянии Voboost

Установщик читает сохранённые файлы Voboost и доступную диагностику Android напрямую через ADB. Он может собрать данные на чистой или частично установленной системе, даже если демона Voboost нет. Архив содержит текущий журнал установщика и результат по каждому источнику. Если доступна только часть данных машины, установщик сохраняет её и сообщает о частичной выгрузке. Если из машины ничего прочитать не удалось, он сообщает об ошибке и сохраняет журнал установщика с компьютера. В обоих случаях код завершения CLI ненулевой. Установщик показывает путь к архиву.

Демон Android записывает полученные события приборки в общий журнал Voboost вместе с событиями Android. Приборка с QNX держит очередь событий в оперативной памяти. При отключении питания ещё не переданные события могут пропасть.

## Перед отправкой

`voboost-installer` сохраняет архив в выбранном каталоге и никуда его не отправляет. Архив можно открыть и проверить перед передачей разработчику.

Сборщик не читает файлы закрытых ключей, session seed, содержимое NV, пользовательские файлы и произвольные снимки памяти. Известные формы секретов скрываются. Сообщения Android и OEM могут содержать другие персональные данные, поэтому перед передачей просмотрите архив. Логи могут содержать версии компонентов, состояние машины, названия агентов и действия пользователя.

## После удаления

Полное удаление стирает логи из машины. Архивы, ранее сохранённые на компьютере, остаются до ручного удаления.
