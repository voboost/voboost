# Vehicle source observations

`VehiclePower` consumes the public `system.read` power projection owned by Voyemu `src/app/runtime/system_observation.cpp`, with owning fixtures in `system_observation.test.cpp`. A complete `Asleep` / `OFF` sample has `display_ready=false`; a complete `Awake` / `ON` sample has `display_ready=true`. Missing/null/partial fields are not false. Android display power is a point sample and is not vehicle ACC: the candidate warm recipe separately requires fixed CAN ACC OFF/ON observations and same-boot/source identity.

Current Java PW retries and cancellation are owned by `VehicleDrivePedestrianWarningAgent.java`: `agent.start.state-read/unavailable-retry` with numeric attempt1..20, and `readiness.cancel/canceled` after canceling an existing readiness task. `no-task` does not prove pending cancellation. Clean stop adopts the current OEM sound setting on restart; FEV retains armed intent across its disabled warm reset. Neither metadata `native.source` nor codec/passive RX proves transfer of controller ownership.

The exact fault is `voboost-inject/daemon/src/emulator_diagnostic.rs::drop_state_reply`, called by `agent_state.rs::route_read_from`; it binds the actual current Java EndpointContext, fixed systemservice PID/starttime, allowed agent/key pairs and owned window token. Root `vehicle-state-observed` records retain actual read/write-readback outcomes. Negative quiet evidence requires the full same-writer export through authenticated live watermark; a missing tail cannot mean no retry.

Existing product cancellation acknowledgement: `control_plane.rs::accept_agent_status` parses the received S document against current desired generation, process, candidate and allowed agent IDs before storing `acceptedStatus`. `AgentRuntimeController.publishStatus` includes every retained cleanup-debt entry and removes that entry only after successful cleanup. A removed PW cleanup entry is not a selected desired ID, so it cannot acknowledge the new desired document as complete. `JavaStopAcknowledgement` consumes this existing channel with unchanged process/epoch/producer, newer document and receipt, while the driver separately checks desired=false and the absent PW row. Receipt sequence is not the canonical-log sequence. `declaredSource` and unowned `readiness.cancel` messages are not agent authority and are not used as stop proof.
