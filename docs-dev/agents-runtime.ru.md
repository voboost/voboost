# Среда агентов

[English](agents-runtime.md) | **Русский**

Исходники и release production агентов находятся в [`voboost-agents`](../../voboost-agents). Агенты являются самостоятельными артефактами полного выпуска Voboost и никогда не встраиваются в `voboost-app.apk`.

## Артефакты выпуска

Один точный agent commit создаёт:

- `agent-common.dex` с общей средой и `ru.voboost.reflect`
- один `agent-*.dex` для каждого логического модуля, общий для его target processes
- `agents.json` с logical agents и target-level `file`, `entryClass`, size и SHA-256
- `agents.json.sig` — raw 64-byte Ed25519 signature точных байтов каталога

Текущие логические агенты и цели объявлены в [release profile](../../voboost-agents/release-profile.json) и соседних Agent.json; [статус агентов](agents-status.ru.md) отражает их классификацию в исходниках. Android resource APK переводов — отдельные артефакты [инструментов перевода](translation-tooling.ru.md), а не DEX-модули. Этот инвентарь не доказывает runtime-допуск.

## Выбор и поколение

Демон проверяет подписанный каталог, читает root-owned `vehicle.json`, вычисляет применимость, зависимости, конфликты и enabled intent и получает выбранный target closure. Приложение скачивает изменившиеся байты, но не вычисляет и не передаёт авторитетный результат выбора.

Принятый набор становится одним immutable generation с парой каталога, точным selection receipt, `agent-common.dex` и всеми различными module DEX из подписанного каталога. Применимость влияет только на производный `agents-selected.json` и модули, которые загружаются в каждый процесс. `current` и `previous` меняются атомарно. Неполный или отклонённый вход не становится активным.

## Доставка в процесс

Демон допускает процесс по стабильным PID/start time, точному `argv[0]`, UID, SELinux context и target из каталога. Injector загружает implant подходящего ABI. Implant создаёт один common classloader и child loader для каждого target module, полученного через удерживаемые дескрипторы; произвольный device DEX path не принимается.

Логический модуль собирается один раз; все его process targets ссылаются на один DEX. Поколение хранит и проверяет файл один раз, а выбор, загрузка и статус сохраняются отдельно для каждой цели. Прежние поколения с отдельными файлами на target остаются читаемыми; старый демон не сможет принять новый shared-file каталог до своей замены.

## Runtime contract

`AgentEntry` проверяет generation и запускает только entries текущего процесса. Каждый агент разрешает structural Java contract до изменения. Неизвестные и неоднозначные OEM capabilities завершаются без изменений.

Agent-to-daemon и daemon-to-agent pipes передают ограниченные typed state, status, logs, desired configuration и acknowledgements. Каждое соединение связано с generation, process start time и epoch. Stop закрывает допуск новых callbacks, завершает ограниченную работу, удаляет принадлежащие агенту hooks и subscriptions, восстанавливает подтверждённое состояние и сообщает результат очистки.

Уже загруженный DEX не выгружается. Работающий процесс сохраняет resident generation до естественного завершения или подтверждённой пользователем перезагрузки.

## Settings surface

В каждом OEM UI process работает один host agent. Feature agents передают contributions через единый process-local registry и не создают независимые menu hooks. Host обнаруживает живые OEM constructors, factories, containers, symbolic resources, theme, dimensions, measurement и drawing. Если структура отсутствует или неоднозначна, host возвращает точный unsupported result и не создаёт частичный или приблизительный интерфейс.

## Исходники и проверки

Production source находится в [`src/main/java/ru/voboost/agents`](../../voboost-agents/src/main/java/ru/voboost/agents), поддержка reflection — в [`ru/voboost/reflect`](../../voboost-agents/src/main/java/ru/voboost/reflect), canonical contracts — в [`voboost-agents/openspec/specs`](../../voboost-agents/openspec/specs).

Host Gradle gates подтверждают Java compilation, D8 closure, target placement, создание и подпись каталога активной build identity, stubs и lifecycle fixtures. Physical injection, OEM UI, device и автомобиль остаются отдельными evidence.

## Реализация и разработка компонента

Репозиторий содержит Java runtime агентов Voboost, `agent-common.dex`, по одному `agent-<id>.dex` для каждого логического агента или исполнителя, подписанный каталог `agents.json` и тестовые OEM fixtures.

Schema 2 сохраняет процесс, файл, размер, SHA-256 и boot каждой цели и требует platform/domain/entryAbi. Android использует android/android/android-java-v1 и entryClass; QNX gauge использует qnx/cluster/voboost-agent3-v1 без entryClass. Корневой clusterRuntime задаёт идентичность native runtime. Все Android-процессы одного логического модуля используют общий файл DEX с одинаковыми размером, SHA-256 и входным классом, сохраняя собственные процесс и boot; конфликт идентичности, повторное использование файла другим модулем и совпадение имён без учёта регистра отклоняются.

Production source компилируется из корневого дерева `src/`. Поколение выпуска хранит полный подписанный набор агентов; применимость влияет только на `agents-selected.json` и загрузку DEX в целевые процессы. В репозитории нет встроенного в приложение набора агентов, `ui-res` и независимо заданных OEM layout profiles.

Команда `./gradlew check` запускает host-level проверки, а `./gradlew buildRelease` собирает набор versionless artifacts компоненты. Host-проверки остаются отдельными от emulator-, device-, vehicle-, protected-signing- и publication-gates.

Полная OEM-матрица требует предварительно собрать host driver задачей `runOemTestDriverBuild` с `-PoemTestDriverInjectProjectDir=/absolute/inject` и project-local `-PoemTestDriverOut=/absolute/receipt.json`, затем передать фактическую identity receipt в `-PoemDriverSha` и абсолютный `-PoemInjectProjectDir` для `check`. Сохраняйте Cargo target и окружение между двумя шагами.

Фактический состав определяют текущие Agent.json и release profile; он отражён в [статусе агентов](agents-status.ru.md). Классификация metadata не доказывает runtime-приёмку.

Отправка мутаций Settings и публикация в очереди сериализованы. Опрос ACK использует защищённый снимок без удержания монитора очереди во время обращения к транспорту или применения проекции; только владелец мутации удаляет свою запись и освобождает токен строки. Сроки ожидания измеряются монотонным временем.

Ошибка отправки, таймаут текущей мутации или ошибка применения снимка добавляет в первую секцию Settings сообщение о неподтверждённом изменении на EN/RU/ZH. Подтверждённый выбор остаётся авторитетным; отсутствие ACK не означает, что изменение не сохранилось. Новая отправленная попытка убирает сообщение этой строки, а завершение прежней попытки не возвращает и не убирает ошибку последней попытки. Повторный ввод, уже ожидающий результата, ничего не отправляет и не считается ошибкой. Обычное описание добавляется и удаляется на месте без замены radio controls и пустого места в нормальном состоянии панели.

Вертикальные отступы Settings генерируются из проверенного снимка исходников `voboost-components` в `tools/component-spacing/`. Верхний и нижний отступ секции, поля и интервалы описаний используют один сгенерированный accessor; внутренние штатные отступы строк нормализуются перед применением defaults. Межсекционный и конечный отступы применяются по одному разу. Снимок не добавляет внешний репозиторий, AAR, шрифты или ресурсы в runtime closure.

Проверяйте snapshot extraction через `./gradlew generateComponentSpacing verifyComponentSpacing`; намеренное обновление исходных defaults описано в [инструментах отступов](component-spacing.ru.md). Живая Settings-приёмка остаётся отдельной от host fixture measurements.

Кнопки действий Qinggan измеряют переведённый текст через `WRAP_CONTENT`, сохраняя штатный стиль и вертикальные отступы; горизонтальные отступы кнопок секций и редактора берутся из проверенного defaults components. Родитель ограничивает ширину, а перенос текста может увеличить высоту. Пара кнопок редактора остаётся горизонтальной, пока текст помещается; иначе кнопки располагаются вертикально со штатным интервалом. В DEX graph регистрируется только объявленный исходник сгенерированного accessor отступов; неизвестные compiled classes по-прежнему отклоняются.

Настройки Voboost поддерживают английский, русский и упрощённый китайский. Каноническое значение профиля и мутации — `zh`; display helpers принимают `zh-CN`, не меняя язык штатной системы и факты автомобиля. При отсутствии китайского текста в старом EN/RU каталоге используется английский. Китайские тексты есть у текущих агентов, общих сообщений и диалога удаления, а также сообщений проверки изменений.

Подсказка запуска объясняет выбранный вариант radio. None не запускает агентов и интерфейс; восстановить запуск можно только с компьютера через `voboost-installer`. Hidden оставляет агентов работающими без вкладки; несколько быстрых нажатий на версию TBOX в разделе «Система» запрашивают её возврат. Interface оставляет агентов работающими и сразу показывает вкладку. Видимый выбор объясняет режим, но не утверждает, что изменение сохранено; после ожидающих или отклонённых мутаций авторитетом остаётся подтверждённая проекция.

При установке hook публикуются шесть ограниченных info-записей `hook.install.frontier`: начало/конец создания callback, начало/конец поиска его метода и вход/возврат native bridge. Записи содержат только идентификатор целевого метода и наличие backup после возврата; значений аргументов вызова в них нет. Последняя граница уточняет этап незавершённого запуска, не меняя поведение hook или startup. Вход в native bridge не доказывает завершение LSPlant; его нужно сопоставлять с native stage markers.

ACK и обычные desired updates используют общий канонический домен EN/RU/ZH из AgentProfile через внешний парсер AgentPlan. Интеграционная регрессия ACK проверяет AgentEntry, настоящий runtime controller и publisher Settings, включая перевод на китайский без удаления вкладки. Только заголовки radio получают горизонтальный отступ Section из источника компонентов; геометрия дочерних controls сохраняется.

Необязательная диагностика `AgentEntry.scheduleMainThreadSnapshot(String)` вызывается проверенным native caller после успешного возврата init. Она запускает один DEBUG-снимок main thread на успешное runtime-поколение в отдельном worker, не в main Handler и не в потоке канонических обновлений. Максимум 24 записи class/method/line/native и этапы с process/PID/Java-thread/state; аргументы, пути и произвольные имена потоков не записываются. Владение Task регистрируется до выполнения. Stop/replacement отменяет наблюдение атомарным флагом без прерывания/логирования Task.cancel и без ожидания потенциально занятого VM stack call; поздний вывод отсечён, каждое событие содержит поколение. Точка съёмки отмечена `post-init-worker` / `may_precede_ptrace_release`: hijack frame не доказывает исходный OEM Binder caller до сопоставления после снятия lease.

Диагностика Launcher до завершения init запускает один независимый worker с задержкой перед executors/reconcile. Если init завершился раньше, выводится dropped; replacement/stop атомарно ограждают поздние записи. Парные font frontier отмечают открытие raw resource, ограниченное чтение и закрытие без байтов/путей и без изменения qualification/fallback. Отсутствие terminal-записи означает неполные данные.

Native hook bridge обязан опубликовать настоящий reflected backup через `HookCallback.setBackup` до доступности target trampoline. Повторная Java-публикация после возврата идемпотентна; unhook сохраняет backup для уже начавшихся callback. Host-тесты bridge проверяют stock semantics; native ordering и приёмка на runtime остаются отдельными доказательствами.

## Native applicability

Optional объект `native` требует `source` и допускает только дополнительный объект `applicability`. Без override нативный исполнитель наследует все пять logical axes: chip, vehicle, android, powertrain и market. Override содержит непустой subset этих axes и непустые уникальные списки значений из logical values. Unknown axes, расширение, пустые списки и неправильные scalar types отвергаются. Generated native registry содержит effective intersection в canonical axis order; неуказанные axes наследуют logical values. Java target/catalog applicability не меняется. Это semantic capability dimensions, а не firmware identities или hash compatibility gates.

PW сохраняет logical Java NXP applicability, а PW и FEV сохраняют logical Java Free/Dreamer applicability. Native backend beta ограничен Dongfeng/8155 Free на Android 9 и 11; нативное выполнение NXP и Dreamer остаётся unavailable до появления их собственных поддерживаемых контрактов и capability probes. `verifyNativeApplicabilityMetadata` проверяет narrowing, inheritance и rejection; `testNativeRegistry` сверяет настоящие generated ID/source/effective metadata. Current-property probe rejection и actual native effect/readback остаются отдельными owning/runtime gates.

## Наблюдения для восстановления автомобильных агентов

Ранние OEM-настройки и наличие CAN-службы проверяет отдельный worker с ограниченной очередью. При временном отсутствии входов повтор выполняется через 250 мс; при запрете доступа или неверной структуре сохраняется диагностическая причина и повтор выполняется через секунду. Основной poll владельца не засыпает и не обходит `/proc`. Отказ проверки готовности до ioctl оставляет агент в ожидании, не расходует попытки команды и не сбрасывает полученную обратную связь. Каждая новая попытка проверяет актуальный выбор пользователя, ревизию входов и свежесть наблюдений. ioctl с неизвестным результатом не повторяется вслепую. Поиск процессов пропускает известные SELinux-домены вне разрешённых целей; неизвестный контекст проверяется повторно с прежней ограниченной частотой. Восстановление планировщика APK ждёт завершения загрузки Android и не блокирует нативные автомобильные агенты.

Нативный владелец различает короткий CAN-кадр, неподдерживаемый пакет ядра, пустую очередь и отказ транспорта. Неподдерживаемые сообщения потребляются без закрытия сокета и сброса известного состояния питания; они не становятся обратной связью автомобиля. Число сообщений за проход ограничено, неподдерживаемые пакеты учитываются отдельно.

Действующий исполнитель CanBusService передаёт проверенные пробами чтения getAccStatus/getVehicleState через существующий аутентифицированный канал команд. Владелец принимает только зарегистрированный процесс/endpoint, объявленный источник и поле, текущую загрузку и ограниченное время наблюдения. Это чтения штатного API, а не новые CAN-события. После действительного разрыва они позволяют восстановить ту же сессию питания без выдуманного нового включения. Наблюдение, снятое до принятия команды, не подтверждает её результат. Пользовательский OFF имеет приоритет во время любого восстановления.

Внедрение в приборку повторяет ожидающее планирование UI в существующем worker без внешнего наблюдателя. Назначить владельца UI до первого engine frame может только callback штатного dispatcher. Принятая задача ещё не означает применённого агента. Временное отсутствие символов проверяется повторно, успешные разрешения кешируются. Применение агента и доставка диагностики не ждут завершения друг друга.

Диагностический снимок native RX сохраняет `firstTargetFrames` для `0x6a`, `0x73` и `0x9a` независимо от кольцевого журнала. Каждая запись содержит исходный кадр, время приёма от начала загрузки, последовательность и эпоху приёмника. Это первое получение текущим процессом демона, включая кадры, отброшенные политикой рабочего состояния; оно не доказывает время первой передачи ECU и не охватывает период до подписки. Переподключение приёмника сохраняет записи, перезапуск демона начинает новое наблюдение.
