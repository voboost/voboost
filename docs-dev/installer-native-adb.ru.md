# Прямой ADB для macOS

[English](installer-native-adb.md) | **Русский**

Один и тот же исполняемый файл macOS подключается к машине по USB или к выбранному эмулятору по локальному TCP. Оба транспорта используют общий связанный код AOSP для пакетов, авторизации, транспорта и shell-v2. USB работает через IOKit, RSA-подпись — через Security.framework. Установщик не запускает исполняемый файл `adb`; ему не нужны ADB-сервер, OpenSSL или специальное разрешение Apple. Windows использует ADB из своего пакета. Linux использует системный исполняемый файл ADB из фиксированных путей backend.

При запуске GUI или консольной операции `--device 1234567` выбирает это USB-устройство, а `--device emulator-5588` — прямой ADB по адресу `127.0.0.1:5589`. Суффикс эмулятора должен быть канонической записью чётного порта консоли; порт ADB вычисляется прибавлением единицы. Отдельных параметров адреса или порта нет. Цель фиксируется на время жизни процесса; режим эмулятора не сканирует USB и другие порты. Параметр без операции открывает GUI. Первое подключение, операции и переподключение сохраняют ровно это устройство; при его исчезновении или отсутствии авторизации другое подключённое устройство не выбирается. Запрос операции для другого serial отклоняется. Выбор устройства в GUI не совмещается с `--dry-run`. Без указания цели обычные GUI и CLI обнаруживают USB-устройства. Справка и проверка пакета не требуют устройства.

Voyemu может сохранять SDK ADB-сервер для своего API управления. Установщик не использует и не перезапускает этот сервер. Независимые тестовые инструменты, например измерение времени кадров лаунчера, по-прежнему могут вызывать внешний SDK ADB.

Локальный процесс эмулятора считается доверенным. ADB AUTH подтверждает ключ компьютера устройству, но не подлинность эмулятора установщику. Другой локальный процесс, занявший порт ADB, может выдать себя за эмулятор и подделать ответы. Явный выбор цели и поколения устройства защищают от случайного смешения операций разных устройств, но не устанавливают личность собеседника. Защита от злонамеренного локального процесса в этот backend не входит.

[`src-tauri/build.rs`](../../voboost-installer/src-tauri/build.rs) собирает исходники из [`adb/sources.json`](../../voboost-installer/src-tauri/adb/sources.json) средствами Xcode для arm64 или x86_64 с C++20, `-Oz` и deployment target macOS 11.0. До компиляции он проверяет существующий реестр исходников, после неё удаляет промежуточные объектные файлы и связывает libc++, CoreFoundation, IOKit и Security. Сборка native ADB ничего не скачивает и не использует заголовки Android SDK.

Исходники AOSP сохраняют copyright и уведомления Apache-2.0. `sources.json` фиксирует upstream commits и идентичность входных файлов; [`NOTICES.txt`](../../voboost-installer/src-tauri/adb/NOTICES.txt) содержит сохранённые уведомление и лицензию. `compat/openssl/rsa.h` объявляет непрозрачный совместимый тип и не содержит реализации OpenSSL. Сохраняйте эти файлы происхождения и лицензирования вместе с исходниками.

Rust-код передаёт абсолютный путь к каталогу ключей; установщик использует `.android` пользователя компьютера. Существующие ключи RSA-2048 в формате PKCS#1 или незашифрованном PKCS#8 используются с соответствующим открытым ключом ADB. При отсутствии закрытого ключа backend создаёт его через Security.framework вне связки ключей и атомарно записывает с правами `0600`; отсутствующий `.pub` восстанавливает. Байты существующего закрытого ключа сохраняются. Backend ограничивает права обычного файла текущего пользователя с одной жёсткой ссылкой через проверенный дескриптор и отклоняет символические ссылки, файлы с несколькими жёсткими ссылками и файлы другого владельца.

Внутренний [C ABI](../../voboost-installer/src-tauri/adb/voboost_adb_api.h) предоставляет асинхронные потоки shell-v2 и фиксированные сервисы `root:`, `remount:` и `reboot:` с ограниченными очередями, сроками выполнения и отменой. Для shell-v2 нужна соответствующая возможность устройства. Поколение устройства не позволяет продолжить старую операцию после переподключения. За время жизни процесса разрешена одна попытка создания host; этот ABI не даёт публичной гарантии совместимости. Закрытый C ABI также подключает один порт консоли эмулятора и повторно соединяется только с этой локальной целью. Сетевое обнаружение, удалённые узлы, pairing и TLS в backend не входят.

Завершение потока управляющего сервиса не доказывает успех root, remount или reboot. Вызывающий код должен проверить ответ, переподключиться и проверить состояние устройства. Host-сборка и тесты протокола не подтверждают работу физического USB или готовность в автомобиле.
