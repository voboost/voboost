# Native runtime шрифтов

[English](cluster-font-runtime.md) | **Русский**

`src/product.cpp` — минимальный перенос сохранённого Runtime2/Agent3 lifecycle. Он допускает авторизованные модули, применяет производное желаемое состояние и сохраняет загруженный код после stop. Единственный native-модуль beta1 — QNX-реализация существующего логического агента `font-cyrillic`; второй галочки и независимого intent нет.

Native-дескриптор использует логическое имя процесса `gauge`. Общий parser каталога связывает эту QNX-цель с исполняемым файлом `/usr/bin/gauge`; `gauge_normal.kzb` — имя ресурса темы, а не подтверждение исполняемого файла `gauge_normal`. Манифест производителя содержит tuple QNX/cluster/Agent3 и точную идентичность native-артефакта; допуск исполняемого файла дополнительно требует защищённую startup-конфигурацию и проверенные OEM build identities. Эмуляторные launch aliases не задают профиль физической машины.

`./gradlew buildNativeCluster` собирает `build/cluster/product/libvoboost-runtime-cluster.so` и `libagent-font-cyrillic.so` через NDK 29.0.14206865 с точными SHA заголовков SDK2/Agent3 из `sdk-v3.lock.json`. `-PclusterSdkDirectory=<path>` выбирает экспортированный SDK. Release orchestration может передать готовый native-каталог через `-PclusterNativeDirectory=<path>`; каталог и проверка bundle закрепляют его точные байты.

Агент требует расширение capability `vbc_font_loader_v1` с подтверждением результата и проверкой размера ABI и сохранённую идентичность сборки libkzcoreui `4078ac45f735e41b1c76c262ebd9ba15`. Отсутствие capability или несовпадение идентичности блокирует допуск. Каждый вход квалифицируется по точному SHA-256; после ограниченного структурного исправления SFNT проверяется точный SHA-256 результата. Два статических буфера общим размером 3 357 136 байт сохраняются до завершения процесса. Stop снимает будущие callbacks и возвращает reload-required, если уже выдавался исправленный буфер. Буферы, которыми пользуются FreeType faces, не выгружаются. Расширение возвращает результат оригинального `FT_New_Memory_Face` и признак созданного face. Состояние `Applied` требует успешной загрузки исправленного шрифта с точным выходным SHA-256 и отсутствия ранее созданных или загружаемых faces при установке callback; иначе сохраняется reload-required. Успешная загрузка до появления UI запоминается и подтверждается после готовности штатного интерфейса. Выключенный модуль не устанавливает callbacks.

Host-проверки покрывают совпадение Java/native на синтетических шрифтах, malformed/unknown/bounds, SHA-256 padding, владение callbacks и Runtime2 lifecycle. `tools/verify-native-font-oem.py --kzb <external-retained-gauge_normal.kzb> --report build/evidence/native-font-oem.json` независимо находит точные шрифтовые идентичности и проверяет оба выходных SHA в памяти. Извлечённые OEM-шрифты не записываются и не включаются в bundle.

В исходном system image Free 6.0.3 (SHA-256 `ed32a05382848e0fb63cb33cdf0de55ec3d088f37aad21637b24c12e22a7a6bf`) SHA-256 libkzcoreui — `954ef479aaa2c4851bc720f28ed4d192251912dd70db21506d85daa6c3284030`; загрузчик KZB вызывает `FT_New_Memory_Face@plt` по RVA `0x43d094`, dynamic table содержит NOW без SYMBOLIC. Это подтверждает только кандидата для loader interposition. Реальные QNX resolution, число вызовов оригинала, загрузка faces, resource reload и физическое поведение машины не проверены. Исходный `gauge_normal.kzb` Free 6.0.3 (SHA-256 `2f0a9f0efe798b6ebaf6c299ccd58453ea4295c864f8d725ffd6ad99369620a7`) прошёл оба точных native/Java преобразования шрифта на хосте. Это подтверждает статическую совместимость входов, но не работу на QNX. Синхронная сверка в constructor выполняется до возврата в OEM startup, однако ранее загруженные dependency constructors faces требуют перезагрузки. Автоматический перезапуск gauge не реализован.
