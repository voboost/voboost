# Приёмка нативного GUI

[English](installer-gui-acceptance.md) | **Русский**

В production установщике сервера автоматизации нет. Необязательный Cargo feature `gui-test` добавляет `tauri-plugin-wdio-webdriver =1.5.0` и capability только во время тестового запуска. На macOS HTTP listener привязан к `127.0.0.1`. Эту сборку нельзя раздавать или включать feature при упаковке релиза.

Соберите тот же frontend и ресурсы, что у проверяемого кандидата, затем нативный исполняемый файл: `cargo build --release --locked --features gui-test --target aarch64-apple-darwin --bin voboost-installer`. Используйте публичные role roots кандидата, его версию, observation directory и подготовленные ресурсы ADB; backend операции остаются настоящими. Полученный файл — диагностический артефакт, а не production DMG.

Запустите диагностическое приложение с двумя переменными: `VOBOOST_GUI_TEST_SERIAL=emulator-PORT` и `TAURI_WEBDRIVER_PORT=PORT`. Feature отвергает другой serial в общем backend parser и оставляет в выдаче устройств только этот эмулятор. При отсутствии или неверной конфигурации запуск блокируется. Эту сборку нельзя использовать с автомобилем.

Из репозитория выполните `node tools/gui/client.ts PROJECT_REQUEST.json`. Пути задаются относительно workspace либо абсолютными внутри него; родительские каталоги должны существовать. Клиент создаёт одну W3C сессию, выполняет действия по порядку и закрывает сессию. Приложение остаётся открытым. Клиент работает только с loopback port и сохраняет дерево/PNG внутри workspace.

```json
{
  "port": 4445,
  "actions": [
    { "op": "wait", "selector": "button", "timeoutMs": 120000 },
    { "op": "tree", "path": "plans/DATE/gui/startup.json" },
    { "op": "screenshot", "path": "plans/DATE/gui/startup.png" }
  ]
}
```

Поддерживаются `tree`, `screenshot`, `click`, `value` и `wait`. `click`/`value` используют CSS selector либо точный доступный target `target: {role, name}`; `value` передаёт `text`. Для `wait` доступны условия `visible`, `absent`, `enabled`, `text` и ограниченный timeout (по умолчанию 120 секунд; условие проверяется каждые 100 мс). Screenshot с `selector` обращается к element endpoint. В upstream macOS плагине1.5.0 этот endpoint пока возвращает всё окно, а не crop; crop нельзя считать подтверждённым. Дерево содержит отрисованные элементы и видимый текст, доступные подписи, состояния, CSS-координаты, число строк и признаки переполнения. `root` указывает в `nodes`; каждый узел содержит `index`, ближайшего включённого `parent` и ссылки `children`. Снимок ограничен 5000 кандидатами и сообщает об усечении. Zustand internals и acceptance tokens не читаются. Подсчёт строк обходит только текстовые DOM-узлы и измеряет их Range, исключая SVG-иконки. Нативную геометрию ещё нужно подтвердить прогоном. Проектный lock на port исключает одновременную работу клиентов; каждый request закрывает только транспортную сессию и оставляет UI открытым.

## Набор кейсов

Нормативный минимальный набор: [G01–G11](installer-gui-test-cases.ru.md). Повторные снимки и общий preflight не считаются отдельными кейсами. Runner записывает ровно G01–G11; общий preflight хранится отдельно в prerequisites. Неавтоматизированные и неполностью проверенные кейсы получают SKIP, параметры отсутствия устройства — отдельные результаты в parameters.G08. Количество успешных стадий не заменяет полноту приёмки.

## Автоматический цикл

`node tools/gui/scenario.ts PROJECT_CONFIG.json` выполняет один локальный маршрут: приветствие и лицензия, подключение, установка и повторное открытие, три значения режима запуска, отмена/подтверждение восстановления и удаления. Язык проверяется на приветствии, Лог — на управлении и во время установки/удаления. Не выполняются отдельные полные маршруты ради языка или снимков. Все изменения устройства идут через GUI; CLI используется только для независимого чтения статуса. Внешний владелец запускает эмулятор и диагностическое приложение.

```json
{
  "port": 4445,
  "serial": "emulator-5582",
  "candidateCli": "/Users/vitaly/voboost/PROJECT-CANDIDATE-CLI",
  "candidateCliSha256": "REPLACE_WITH_64_HEX_SHA256",
  "appExecutable": "/Users/vitaly/voboost/DIAGNOSTIC.app/Contents/MacOS/voboost-installer",
  "appSha256": "REPLACE_WITH_64_HEX_SHA256",
  "output": "plans/DATE/UNIQUE-GUI-RUN",
  "operationTimeoutMs": 600000
}
```

Используйте новый output каталог для каждого прогона; его родитель должен существовать. Цикл требует чистого отсутствующего продукта; предыдущую установленную версию предварительно удалите через GUI её установщика. Перед первым install сверяются SHA256 read-only CLI и immutable test-only metadata native app: exact serial, port и schema. Metadata не существует в production сборке. Не подменяйте эту проверку ручным DOM injection. Test-only WebView отключает background throttling на поддерживаемом macOS, не активируя окно и не меняя настройки ОС.

`report.json` атомарно обновляется после каждой стадии, содержит PASS/FAIL/SKIP, длительность, target identity и связь JSON/PNG с case ID. После FAIL дальнейшие стадии получают SKIP и не выполняют мутации. Невоспроизведённый транспортный сбой не отмечается пройденным. Для отдельной проверки недоступного устройства внешний владелец выключает назначенный эмулятор, запускает UI с начала и задаёт `availabilityOnly: true`: runner проходит лицензии, проверяет searching/disabled Next и Log off/on без установки. Потеря физического USB остаётся отдельной проверкой.

Client поддерживает `guard` с `serial` и `settle`. `settle` пытается дождаться двух animation frames и возвращает явный fallback через 350 мс, если кадры не приходят в фоне; HTTP вызов ограничен 5 секундами. Visibility и активные конечные animations сохраняются в результате. Capture сравнивает DOM до/после PNG и допускает до трёх попыток с уникальными именами; нестабильные результаты не принимаются. Каждый PNG имеет visualStatus REVIEW_REQUIRED: ни fallback, ни стабильный DOM не доказывают соответствие пикселей, их просматривает человек. Обычный screenshot timeout остаётся 120 секунд. Failed stage runner и отсутствие fixture проверяются командой `node --test tools/gui/client.test.ts tools/gui/scenario.test.ts`.

После успешной установки runner проходит «Далее» → экран завершения, проверяет Log, нажимает «Завершить», ждёт закрытия приложения и открывает тот же проверенный по SHA256 диагностический `.app` командой `open -g -n` с теми же serial/port. Это повторный запуск приложения в фоне, без изменения lifecycle VM. Автоматический повторный запуск пока реализован только на macOS. `beforeUninstallGate` необязателен: путь к проектному JSON файлу; при его наличии runner ждёт `{"continue":true}` перед удалением, чтобы внешний владелец снял дополнительные наблюдения. Ожидание ограничено `operationTimeoutMs`.

Runner отвергает возвращение чекбокса «Полная диагностика», проверяет компактный лог и соседство кнопки копирования. Во время установки/удаления действия изменения заблокированы, Лог остаётся доступным. Неполная матрица тем, размеров окна и меню лицензий не выдаётся за пройденный G11.

## Вехи операции и размеры окна

Начальный размер окна — 1060×740, минимальный — 900×640; размер можно менять. На невысоких экранах отступы компактнее, а сведения об установке при достаточной ширине занимают две колонки. Прокрутка остаётся резервом для маленьких окон, длинной диагностики, лицензии и лога, чтобы элементы не обрезались. Обычные экраны проверяются при начальном размере окна и разрешении рабочего стола 1280×800.

При установке, восстановлении и удалении подпись индикатора следует закрытым вехам backend: подготовка, передача файлов, применение изменений, перезагрузка и ожидание подключения, проверка и очистка. Подробности транспорта остаются в логе. Подпись обозначает текущую наблюдаемую фазу; проценты не выдумываются, пропущенные фазы не объявляются выполненными. Все окна gui-test открываются без фокуса, в том числе без visual-режима, и не закрепляются поверх других окон; обычный пользовательский запуск production не меняется. Снимки в фоне с принудительным завершением скрытых конечных анимаций не подтверждают реальную длительность анимации.
