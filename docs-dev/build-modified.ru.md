# Пересобрать и установить изменённый Voboost

[English](build-modified.md) | **Русский**

Собирайте из репозиториев продукта и компонентов с согласованными ревизиями. Упаковка не создаёт и не требует архивов исходников. Сохраняйте лицензии, уведомления и патчи сторонних компонентов рядом с их исходниками.

APK Android-courier содержит свои MIT-документы и уведомления зависимостей Android/JVM. Уведомления native- и Rust-компонентов находятся в поставке установщика и доступны через меню Licenses; в APK courier они не копируются. Исходные тексты уведомлений и сведения об их происхождении сохраняются.

macOS-упаковщик использует ULMO с `udif-chunk-size=8192`: этот вариант выбран сравнением одного подготовленного тома с UDZO при `zlib-level=9`. Обычная сборка создаёт один сжатый образ. Ключ задаёт размер блока, а не уровень LZMA; недокументированный уровень LZMA не предполагается. Ресурсы frontend внутри исполняемого файла не сжимаются, чтобы DMG мог сжать их вместе.

Android implant статически включает закреплённые LSPlant и dex_builder с одной копией статического C++ runtime на ABI. Инициализация и вызовы перехватов LSPlant выполняются напрямую; отдельная shared library LSPlant не поставляется. Карта линкера `voboost-inject/implant/implant.map` сохраняет функции загрузчика и ABI исключений, RTTI и выделения памяти. `make check-prebuilt` проверяет экспорты и зависимости обеих Android ABI. Изменение карты запускает повторную линковку; после изменения контракта нельзя использовать прежние prebuilt-библиотеки.

## Подготовить рабочий каталог

Получите репозитории продукта и компонентов с согласованными ревизиями в одном рабочем каталоге. Инициализируйте необходимые подмодули и сохраните патчи проекта. Упаковщик использует это дерево напрямую, без архива исходников.

Нужны Node 24.13.0, npm 11.6.2, Rust 1.98.0, JDK 17, Android platform 34, build-tools 34.0.0 и NDK 29.0.14206865. Для macOS-сборки также нужны Xcode command-line tools, CMake, Ninja, `cargo-ndk` 4.1.2, OpenSSL, `keytool`, `jq` и штатные утилиты macOS для работы с архивами. Установите Rust targets `aarch64-linux-android`, `aarch64-apple-darwin` и `x86_64-apple-darwin`. Установите зафиксированные npm-зависимости командой `npm ci --ignore-scripts` в `voboost`, `voboost-inject` и `voboost-installer`; Gradle wrappers получают зафиксированные зависимости самостоятельно. Задайте `ANDROID_SDK_ROOT` и `ANDROID_NDK_HOME` для установленного SDK и NDK. Заранее загрузите Cargo-зависимости release tooling: скрипты вызывают Cargo в offline-режиме.

Измените нужные исходники. Для стороннего native-кода сохраните зафиксированную upstream-базу и обновите патч проекта вместе с существующим контрактом исходников в `voboost-inject/tools/prepare-native-third-party-source.ts` или `prepare-libsepol-source.ts`. Сохраните проверку подписей и согласованные роли подписи. Локально зафиксируйте изменения компонентов, затем запишите новые commits в оба product definitions:

```sh
node voboost/tools/release/prepare-source-pins.ts "$PWD" --write
git -C voboost add release/version.toml release/1.0.0-beta1.toml
git -C voboost commit -m 'Use local modified source pins'
```

## Собрать со своими ключами

Выполняйте команды из корня распакованного рабочего каталога. Каталоги ключей и результата должны быть новыми абсолютными путями вне репозиториев исходников, временных каталогов, результатов сборки и кэшей. В примере они создаются рядом с репозиториями:

```sh
cargo fetch --manifest-path voboost/release/Cargo.toml --locked
voboost/release/init-local-test-authority.sh "$PWD/local-authority"
voboost/release/build-local-beta1.sh "$PWD" "$PWD/local-authority" "$PWD/local-modified-build"
```

Сборщик подписывает согласованный комплект APK, каталоги агентов и продукта, разрешение восстановления и native-роли вашими ключами, встраивает соответствующие открытые корни доверия, проверяет комплект и создаёт macOS DMG. Храните закрытые ключи отдельно от публикуемых файлов и сохраните их для следующих сборок. Производственные закрытые ключи не поставляются и не требуются. Итоговый каталог содержит DMG, подписанный комплект, сведения об исходниках и артефактах и открытые корни доверия. Рабочий каталог сохраняется как `local-modified-build.work`.

## Установить полный изменённый комплект

Используйте поддерживаемое устройство с разрешения владельца, включённой отладкой по USB и необходимым root-доступом. Если существующий APK подписан другим сертификатом, сначала удалите его собственным установщиком. При смене корней подписи нужен полный согласованный комплект: замена одного подписанного helper не пройдёт проверку.

Подключите созданный DMG и подставьте фактические путь тома и серийный номер:

```sh
/Volumes/Voboost/voboost-installer --install --device SERIAL
/Volumes/Voboost/voboost-installer --status --device SERIAL
```

Успешная host-сборка не подтверждает приёмку на устройстве, эмуляторе или автомобиле. Для таких выводов выполните соответствующие acceptance gates с точным изменённым пакетом.
