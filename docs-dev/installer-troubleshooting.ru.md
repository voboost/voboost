# Диагностика проблем

[English](installer-troubleshooting.md) | **Русский**

## Обзор

Не обходите проверки подписи, descriptor, device lock или terminal verification. Сначала сохраните точный текст ошибки и безопасный лог, затем определите слой: host, packaged GUI, CI/signing, ADB/device или vehicle.

## Проблемы установки приложения

### Windows

При SmartScreen или требовании Microsoft-verified app проверьте официальный источник и подпись файла; не отключайте защиту системы ради неизвестного бинарника. Если блокирует antivirus, сохраните verdict и digest файла для разбора, не добавляя широкое исключение.

### macOS

Сообщения об unidentified developer или damaged app обычно указывают на signing/notarization/quarantine либо повреждение байтов. Повторно скачайте релиз, сверьте digest и используйте поддерживаемую архитектуру. Crash на Apple Silicon разбирайте по packaged artifact и crash report; локальный dev build не заменяет эту проверку.

## Проверка пакета

Установщик работает офлайн со встроенным выпуском. Если загруженный пакет повреждён, получите его целиком из выбранного канала и проверьте опубликованную identity до запуска. Замена встроенных файлов не исправляет проверку комплекта. Ошибки сети/TLS в Android OTA относятся к [приложению](application.ru.md).

## Проблемы подключения

`No device found` требует проверки USB, режима отладки и `adb devices`. Для `unauthorized` подтвердите запрос на устройстве; для `offline` переподключите транспорт и дождитесь canonical state. При нескольких устройствах выберите точный serial: installer не должен угадывать.

## Ошибки установки

`Root access not available`, `remount failed` и `APK installation failed` относятся к разным этапам и не должны маскироваться общим успехом. Не выполняйте вручную внутренние device commands: сохраните report и используйте штатный retry под тем же per-device lock. При зависании дождитесь operation deadline; принудительное завершение host не отменяет необходимость recovery при следующем запуске.

## После установки

Если приложение не появилось, проверьте terminal verification и установленный package, а не только launcher. Crash после запуска требует logcat и точной installed APK identity; не приписывайте его installer без evidence.

## Получение помощи

Приложите версию установщика, операционную систему и архитектуру компьютера, идентичность выпуска, безопасный лог, канонический код ошибки, вывод `adb devices` без лишних персональных данных и шаг сбоя. Не отправляйте токены, приватные ключи, cookies, подтверждения лицензии или закрытые исследовательские материалы.

## Частые вопросы

- Доступность функций определяется профилем машины и runtime-проверками контрактов агентов; установщик не выбирает прошивку по версии или бинарному отпечатку
- Требования к root задаются выбранным поддерживаемым workflow; installer не должен скрытно получать root
- Влияние на гарантию зависит от юрисдикции и условий производителя; техническая документация не даёт юридической гарантии
- Удаление поддерживается только штатным authenticated uninstall с terminal absence check
- Installer обрабатывает минимально необходимые технические данные и не должен отправлять их без заявленного канала
- USB debugging нужен для фиксированного ADB workflow установки и проверки
- Для каждого автомобиля операция выполняется отдельно с собственным canonical device lock и evidence
