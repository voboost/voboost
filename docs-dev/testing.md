# Testing and evidence

**English** | [Русский](testing.ru.md)

Every result names its exact revision, artifact, environment, action, and observable outcome. Host, emulator, device, and vehicle gates are independent.

| Gate | Proves | Does not prove |
| --- | --- | --- |
| Host | parsers, schemas, build graphs, final-byte identity, package structure | Android or OEM runtime |
| Emulator | install/update/reboot/recovery on the named rooted Android image | vehicle OEM contracts |
| Device | PackageManager, root, init, SELinux, ptrace, ART on named hardware | vehicle UI, CAN, audio, driving behavior |
| Vehicle | exact release behavior on named model and firmware | other models or firmware |

## Host-only emulator driver

The ordinary installer accepts the same `--device` operation for USB vehicles and prepared emulators. Emulator UI observations, screenshot scenarios and fault orchestration execute in the root-owned `tests/emulator/driver/adb` tool, `emulator-driver`; they are not installer commands and are not packaged in a DMG. The installer binary refuses compilation with the tool-only feature.

Gradle emulator tasks build the tool through `compileEmulatorDriver` using the existing Android SDK and shared release Cargo cache. Set `ANDROID_SDK_ROOT` or `ANDROID_HOME` to that SDK; the task selects Java 17. Direct Node tools use the same cached executable, or the absolute `VOBOOST_EMULATOR_DRIVER` override.

The closed invocation is `emulator-driver --emulator-check /absolute/request.json --device emulator-5588 --candidate /absolute/voboost-installer`. The driver rejects USB serials and noncanonical emulator endpoints. It asks the selected ordinary installer to verify its own package. Normal removal is delegated to that same installer's public `--uninstall --device` operation; observation and fault evidence bind both executable paths. Product installation and updates continue to run the ordinary candidate directly. Host tests do not establish live emulator acceptance.

## Component host gates

`voboost-app` checks the headless manifest, JobScheduler ownership, download/crypto paths, socket transport, APK package/version/signer evidence, and minified inventory.

`voboost-agents` checks Java compilation, D8, exact target placement, catalog/signature, stubs, lifecycle, dynamic OEM surfaces, and rejection of legacy `ui-res` inputs and numeric OEM resource profiles. Separate translation resource checks are described in [translation tooling](translation-tooling.md).

`voboost-inject` checks Cargo/C/C++, operation contracts, APK identity, process admission, ptrace rollback, role signatures, full product activation, SELinux policy, and Android cross-build.

`voboost-installer` checks frontend/Rust behavior, startup routing, typed management, CLI routing, offline runtime, and the exact Windows, macOS, and Linux package structures.

`voboost` checks source definitions, real pinned-tool APK identity extraction, rejection of substituted evidence with unchanged APK bytes, Draft 2020-12 plus semantic manifest conformance, exact closure hashing, automatic reuse, canonical restore production/signature/staleness, docs structure, links, language pairs, and formatting.

In deferred image mode, launcher first-page normalization uses the closed `launcher-page-observe` request with two independently generated 64-hex nonces. Paired root receipts bind direct inner grid metrics, the focused primary window and process/generation lifetime; independent boot observations and before/after/fresh Accessibility captures correlate actual labels and bounds. The concrete native `AllAppBarView` has a captured Accessibility class of `androidx.recyclerview.widget.RecyclerView`; these are distinct profiles. Empty feature injections do not disable the common observation endpoint. Authorized image mode retains its PNG indicator check. Case 12 first observes the signed launcher checkbox disabled, captures the fixture-absent original grid, and checks that independent resident status has no selected launcher injection before enabling it. A preenabled or unobservable checkbox remains unavailable without an automatic reset. The preinstall case 1 stock capture stays unchanged. Host dispatcher and malformed-receipt tests do not establish runtime case 12 drag/reboot behavior or visual acceptance; those remain separate runtime gates.

## Cross-system release gates

Before publication, one exact closure must pass clean component builds, signature and inventory checks, draft re-download, Windows/macOS/Linux offline package tests, rooted Android 9 emulator flows, named device checks under SELinux Enforcing, and every vehicle gate declared in the source definition.

A host result never substitutes for a required emulator, device, or vehicle result.

## Synthetic font test fixtures

The four TTF files in `voboost-agents/src/test/resources/font/cyrillic/` are original Voboost assets under that repository's MIT license. They use numeric metrics and four-point rectangles, not external font outlines. Each has `.notdef`, 66 distinct core Russian mappings, ten SFNT tables, valid simple outlines and checksums. Regular uses format-12 cmap/long loca; semibold uses format-4 cmap/short loca. The corrected pairs change 64 and 63 metrics respectively, preserving deliberately wide rectangles. They were constructed independently of the production patcher.

`FontCyrillicFixtureCommitmentTest` independently checks their identities, SFNT directory, mappings, outlines, metrics, permitted byte changes and checksums. ## Emulator test stages

Use `./gradlew --offline emulatorCheck -PcandidateDmg=/absolute/current.dmg -PpreviousDmg=/absolute/previous.dmg` to run the implemented emulator cases. The previous DMG is required for the update case. If it is missing, the runner executes the other cases and reports the run as incomplete.

The shared `config/config-voyemu.json` declares the `installer` and `agents` machine roles. The local `config/config-voyemu-local.json` maps the declared machine names to paths. The runner uses the configured machine for the other role when only one mapping is available. When both paths resolve to the same machine, it runs installer tests first and then prepares the installed candidate for agent tests. Different canonical paths run concurrently. Both lanes use one read-only mount of the current DMG. Voyemu starts the two sessions in order and then runs both machines concurrently. Pass `-PmachineName` to use one configured machine explicitly.

| Task | Scope |
| --- | --- |
| `emulatorPrepare` | Establishes the persistent guest state for one group and closes any preparation session. The installer group starts with an absent product. The agent group installs, updates, or reuses the selected candidate. |
| `emulatorStart` | Starts the test session, waits for Android and required QNX delivery, and records its identity. |
| `emulatorTest` | Executes the selected cases in the recorded session. |
| `emulatorReconcile` | Reads the retained operation's supported postconditions without replaying input. A prior failed test remains failed. |
| `emulatorStop` | Restores owned setup changes and closes the session and package mounts after verified cleanup. |
| `emulatorCheck` | Runs all four stages and collects the result of each selected lane. |

To run a group, add `-Psuite=agent-pedestrian-warning`. To select a case, add `--tests '*AgentPedestrianWarning.hidesOffIconFromDrawer'` to `emulatorCheck` or `emulatorTest`. Use `--test-dry-run` to list the selected cases without starting Voyemu. The `generic` group needs no DMG or QNX.

`AgentPedestrianWarning.keepsSoundDisabledAndIconsUnchangedAfterMultimediaRestart` selects OFF through the original drawer, checks the independent CAN state and saved intent, compares the cluster region with its reviewed reference, and captures the actual drawer icon. After a multimedia restart it observes OFF without another toggle and repeats both image checks. The drawer OFF images must be pixel-identical across the restart and distinct from ON. This case does not force the QNX sound fixture. Unknown input remains owned until supported read-only reconciliation; unsupported postconditions are rejected.

To call stages separately, use the same group, machine and DMG options for each command. The runner retains private stage receipts and reports in `build/emulator-work/lifecycle`, or under the directory passed as `-PcheckWorkDir`. Run `emulatorStop` after a standalone test, including a test failure. If a mutation outcome is unknown, cleanup keeps the owner and evidence for reconciliation. On an assigned test machine, `-PprepareExisting=uninstall` authorizes preparation to remove an existing installation when needed.
