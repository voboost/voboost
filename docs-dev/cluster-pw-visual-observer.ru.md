# Значок PW на приборке

[English](cluster-pw-visual-observer.md) | **Русский**

QNX-агент `vehicle-drive-pedestrian-warning` скрывает штатный OFF-значок пешеходного звука в процессе `light`. Он получает включение через обычный жизненный цикл native-агентов от демона QNX. Агент не читает CAN, не определяет фактический звук и не ждёт периодических разрешений от Android.

## Сохранённая настройка

Мультимедиа передаёт настройку по существующему аутентифицированному каналу Cluster. [Демон QNX](../../voboost-inject/cluster/native/src/engine.rs) проверяет запрос и атомарно сохраняет Desired в собственном постоянном хранилище. После перезапуска он загружает сохранённую конфигурацию. [Контроллер](../../voboost-inject/cluster/native/src/controller.rs) передаёт её в native runtime: включённый модуль получает `start`, выключенный — `stop`.

Отдельный файл состояния PW не нужен. Потеря связи с мультимедиа не отменяет сохранённый выбор и не требует heartbeat. Более новая принятая настройка заменяет предыдущую. Повтор старого запроса не должен возвращать выключенную функцию. Pairing, проверка подписанного запроса и атомарная запись относятся к общему протоколу настройки; удалять эти проверки не требуется.

## Применение и восстановление

[Модуль](../../voboost-agents/src/main/cpp/agents/vehicle/drive/pedestrianwarning/src/agent.cpp) выполняет OEM-вызовы только на UI-потоке `light`. Backend подтверждает текущий Screen, прикреплённый узел `SoundEnable`, тип `Node.Visible` и владение источником свойства. Совместимость определяется пробами символов, типов и поведения, без списков firmware/APK SHA.

Маска добавляет собственный источник `false` в `Node.Visible` проверенного контейнера значка. Штатные источники видимости дочерних узлов сохраняются. Она не перезаписывает OEM-значение и не отправляет команды машине. При `stop` удаляются только собственные source и cookie. Затем действует актуальное штатное значение, включая OEM-обновления, пришедшие во время скрытия. Смена корня UI требует снятия старой маски и новой проверки владельца. Ошибка снятия сообщает `reload-required`, а не успешное выключение.

В рабочем пути нет зависимости от live-lease, возраста CAN-наблюдения или временного proof. Специальный periodic PW courier не планируется. Сохранившиеся исходники старого канала ещё требуют отдельного удаления после проверки ссылок; они не являются источником разрешения для маски.

## Автоматические проверки

Из корневого `voboost`:

```sh
CXX=/absolute/host/clang++ ./gradlew testPwNative
```

Компилятор должен иметь настроенный host SDK. Product-owned runner компилирует реальные `agent.cpp` и `mask.cpp` с colocated-тестами. Проверяются запуск без CAN/live-lease resolver, продолжение работы без heartbeat, остановка и повторный запуск, владение маской и ошибка восстановления. Общие Rust-тесты QNX отдельно проверяют принятие настройки, запись, перезапуск, сохранённый OFF, конфликт и повреждение хранилища.

После release-сборки требуется runtime-проверка: подтвердить сохранённую настройку и фактический `applied` текущего модуля `light`; проверить виден → скрыт → восстановлен; повторить после перезапуска QNX и без соединения с мультимедиа. Штатный видимый значок для fixture задаётся существующим входом виртуального MCU и отмечается как тестовый аппаратный вход. Он не доказывает весь физический путь CAN→MCU.

Целевые тесты запускаются на подготовленном эмуляторе. Они используют VehicleSetting и левую шторку при включённом агенте и записывают независимый вход виртуального MCU. Для темы Classic на A9 все пиксели области 46×46 по координатам x841/y102 сравниваются с утверждёнными WebP-эталонами без потерь. Перед снимком скрытого значка тест ждёт подтверждения применения от текущего агента QNX. После выключения агента тест ждёт подтверждения и сверяет восстановленный штатный значок с видимым эталоном.
