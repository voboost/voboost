# Минимальная приёмка GUI beta1

[English](installer-gui-test-cases.md) | **Русский**

Это набор поведенческих кейсов, а не число снимков. Каждый кейс получает один итог PASS/FAIL/SKIP с причиной и ссылками на доказательства. Подготовка окружения — условие запуска, а не отдельный пользовательский кейс. Старые результаты не становятся результатами нового кандидата.

Перед запуском записать хеши кандидата и диагностического приложения, serial, тему и масштаб; проверить принадлежность сессии и исходное состояние продукта. Изменения устройства выполняет один владелец через GUI. Независимые чтения состояния допустимы. Для диагностической сборки действуют ограничения из [инструкции запуска](installer-gui-acceptance.ru.md).

## Основной маршрут

| ID | Действия | Критерий |
| --- | --- | --- |
| G01 | Приветствие → лицензия → подключение → подготовка | Без согласия продолжение запрещено; возврат сохраняет корректное состояние; показываются модель и версии, доступность установки соответствует устройству. |
| G02 | Установить на чистое устройство; завершить и открыть установщик снова | Видны накопленные вехи, повторное нажатие не запускает вторую операцию; после перезагрузок продукт установлен, повторный запуск открывает управление. |
| G03 | В управлении последовательно выбрать hidden, none, interface; перечитать конфигурацию | Каждое значение записано и перечитано; выбор не останавливает работающий продукт немедленно. Проверка следующей загрузки принадлежит отдельному runtime-плану. |
| G04 | Экспортировать логи; повторить с отменой сохранения | Архив читается и содержит логи; отмена не выдаёт ошибку и не меняет устройство. |
| G05 | Открыть восстановление, отменить; повторить и подтвердить | Отмена не меняет устройство; подтверждение выполняет восстановление и возвращает наблюдаемый итог. |
| G06 | Открыть удаление, отменить; повторить и подтвердить; открыть установщик снова | Отмена сохраняет установку; при выполнении виден прогресс, дублирование запрещено; независимо подтверждены отсутствие продукта и маршрут новой установки. |
| G07 | На совместимой повреждённой установке той же версии выбрать переустановку | Доступна явная переустановка через лицензию; операция восстанавливает продукт. Неизвестная идентичность и несовместимость не обходятся. Проверка другой версии — отдельный параметр host-теста, не второй полный GUI-цикл. |

G01–G06 выполняются одной последовательностью без повторной установки ради снимков, языка или кнопки «Лог». G07 требует отдельного исходного состояния; его нельзя объявлять пройденным по здоровой установке.

## Ошибки и общие элементы

| ID | Действия | Критерий |
| --- | --- | --- |
| G08 | Запуск без устройства → подключение; отдельно предъявить unauthorized и неподдерживаемое устройство | У каждого состояния понятное сообщение и корректно заблокированные действия; подключение восстанавливает маршрут. Разные причины — параметры одного кейса, результаты фиксируются отдельно. |
| G09 | Разорвать транспорт до операции, затем подключить | Установка не начинается по устаревшему состоянию; после повторного обнаружения доступен корректный маршрут. |
| G10 | Разорвать транспорт во время изменения устройства; подключить и выполнить разрешённое восстановление/повтор | Нет ложного успеха, параллельной операции и бесконтрольного повтора; состояние перечитывается, восстановление завершается. Потеря транспорта и выключение VM — разные воздействия. |
| G11 | Один раз проверить общий интерфейс: RU/EN, обе темы, обычный и минимальный размер окна, Лог закрыт/открыт, копирование, меню лицензий | Нет обрезки и переноса кнопок, недоступного управления или сдвига основного содержимого уведомлением; лог можно открыть и скопировать, лицензии читаются. Во время G02 и G06 отдельно проверить доступность Лога и блокировку действий. |

Ошибка самого backend при restore/uninstall проверяется параметризованными компонентными тестами диалога и результата, без повторения полного нативного маршрута для каждой одинаковой ошибки. G10 остаётся настоящей интеграционной проверкой. Фикстура не считается проверкой USB; физический USB отмечается отдельно и не требуется подменять его остановкой VM.

## Отчёт без повторов

На каждый ID — действия, ожидаемый и наблюдаемый результат, сборка, среда и доказательства. Для параметров отдельные строки результата внутри ID. Снимки сохраняются для разных экранов основного маршрута, диалогов и отличающихся ошибок. Повторно открытый неизменённый экран ссылается на первый снимок. JSON сохраняет проверенные значения и состояния кнопок; промежуточные диагностические кадры остаются приложением, а не новыми кейсами.

RU/EN, тема и Лог — параметры G11, а не множители всех операций. Обе темы и языка проверяются на устойчивых экранах без повторной установки. Изменение только иллюстраций или иконок не требует повторять установку и автомобильные FEV/PW. Изменение backend операции требует затронутого интеграционного кейса и его восстановления; финальный кандидат проходит основной маршрут.

## Граница автоматизации

Компонентные тесты: блокировки лицензии, матрица совместимости/версий/здоровья, отмены диалогов, ошибки команд, локализация, доступность общих элементов. Нативный локальный GUI: G01–G11 с реальным backend там, где нужна операция; неподготовленный fault fixture означает SKIP. Упаковка отдельно проверяет отсутствие WebDriver и диагностического backend в production. Снимок помогает визуальной оценке, но не заменяет проверку состояния устройства. Запуск эмулятора в CI этим планом не требуется.

Корневой Java-контракт `GuiReport` в `tests/common` описывает результаты кейсов, предварительных условий, фикстур, отдельных параметров G08 и общих элементов управления G11. Для PASS нужны проверенная фикстура и свидетельство; ошибка предварительного условия, кейса или параметра запрещает последующие мутации. Полный PASS G08 требует успеха всех трёх параметров доступности. Полный PASS G11 требует PASS G02 и G06, успеха всех параметров общих элементов управления и того, чтобы каждый параметр Лога и блокировки мутаций был записан с проверенным свидетельством внутри явно открытого окна операции G02 или G06. Хостовый контракт фиксирует только структурную последовательность начала и завершения; он не доказывает фактическое выполнение UI или backend, что остаётся задачей интеграционного runner. Для прежнего SKIP необходимо указать причину, которая определяет BLOCKED или NOT_RUN. Контракт не выполняет операции GUI; полная интеграционная и эмуляторная приёмка остаётся BLOCKED.
