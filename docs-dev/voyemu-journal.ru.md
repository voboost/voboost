# Журнал резервирования отправки Voyemu

Журнал на хосте — отдельный компонент с безопасным отказом. Метод `VoyemuClient.lookupReserved` подключает только чтение; отправка мутаций остаётся заблокированной. Журнал не устанавливает идентичность машины, область мутации и их связь с байтами запроса; будущий вызывающий код должен установить их независимо до интеграции.

Для всего домена мутации нужен отдельный доверенный локальный каталог. Все участвующие процессы должны использовать один каталог и inode блокировки; права доступа должны исключать замену, удаление, символические ссылки и внешнюю запись. Защита журнала не распространяется на другие каталоги и хосты, не участвующие процессы и ненадёжные файловые системы. Байты запроса могут содержать чувствительные данные; ограничьте доступ к каталогу.

`open` получает исключительную межпроцессную блокировку. `reserve` создаёт необратимую единственную запись с областью, идентичностью машины, ID запроса и точными байтами запроса и принудительно записывает файл и каталог. При будущей отправке вызывающий код должен удерживать блокировку до окончания отправки и сверки. Ошибки, частичные и существующие записи блокируют новое резервирование. После сбоя или неизвестного результата повторно отправлять запрос нельзя; NOT_FOUND при поиске операции не доказывает отсутствие эффекта. `inspect` только читает структурно корректную запись после проверки переданных области и идентичности. Он не сверяет их с машиной и не обнаруживает каждое структурно корректное повреждение.

Для восстановления необходимо остановить всех участников, сохранить доказательства, независимо установить удалённое состояние и идентичность машины и документировать решение человека перед созданием нового домена. Не заменяйте блокировку или запись, пока участники могут работать. API не обеспечивает эту процедуру. Корректность также зависит от поддержки блокировок, атомарного создания и принудительной записи файла и каталога операционной и файловой системами; тесты на хосте не доказывают сохранность при потере питания.

Тесты Java на хосте проверяют перезапуск, конкуренцию и смерть процесса, усечение записи на каждом байте, неверную кодировку, несовпадение идентичности и неизменяемость резервирования. Они не проверяют интегрированную отправку, удалённую сверку, работу VM или потерю питания. Резервирование не доказывает отправку или завершение операции.

`VoyemuClient.lookupReserved` создаёт только запрос на чтение после сверки точных байтов исходного запроса, request ID, вычисленной области и переданной вызывающей стороной метки identity. Эта метка сама по себе не подтверждает identity удалённой машины. Отправка мутаций по-прежнему заблокирована; `NOT_FOUND` не разрешает повтор. Host-тесты проверяют несовпадения, повреждённый журнал и timeout чтения, но не доказывают выполнение мутации или восстановление после потери питания.

`State.RESPONSE` подтверждает только внешний конверт ответа lookup. `assessReservedLookup` отклоняет некорректные или несовпадающие доступные идентификаторы и возвращает `UNVERIFIED` для pending, unknown, terminal, ошибок и timeout; он не проверяет terminal receipt и не подтверждает identity машины или видимый эффект. Результат не разрешает повторную отправку.
