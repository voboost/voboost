# Сборка и распространение

[English](installer-build.md) | **Русский**

## Инструменты и источники версий

Интерфейс собирается TypeScript и Vite, desktop shell — Tauri и Rust. Версии Node.js, npm, Rust, Tauri и зависимостей берутся из файлов репозитория и lock-файлов. Сборка выпуска не обновляет их автоматически.

Все поддерживаемые Rust-команды используют release-профиль: локальный запуск Tauri, тесты, Clippy, проверки target-платформ в CI и упаковка. Репозиторий не создаёт отдельный каталог `target/debug`. Vite может запускать frontend development server, но настольная Rust-программа остаётся release-сборкой.

Чистый checkout готовится командой `npm ci`. Основные проверки:

```text
npm run typecheck
npm run lint:check
npm run format:check
npm test -- --run
npm run test:build
npm run build
npm run test:rust
npm run lint:rust
```

## Платформенные пакеты

- macOS — отдельные DMG `arm64` и `x86_64` с программой соответствующей архитектуры и встроенным прямым ADB и одной плоской подписанной product closure в `Contents/Resources`
- Windows x86_64 — один portable executable с closure и точным набором из трёх файлов ADB
- Linux x86_64 — один CLI tar.bz2 с закреплёнными лицензиями и уведомлениями, mode `0755` и без встроенного ADB

В beta1 нет доверенной подписи издателя для настольных пакетов: macOS использует ad-hoc подпись, Windows и Linux выпускаются без подписи. Интерфейс обязан заранее объяснять возможное системное предупреждение и не скрывать происхождение файла.

Локальная проверка macOS принимает уже собранные программы и уже подписанную product closure; она не собирает Android-компоненты и не создаёт подпись продукта:

```text
node src/build/offline-package.ts build-mac-dmg \
  <Voboost Installer.app> <flat-signed-closure> \
  <product-public-key.pem> <product-role.sig> <restore-role.sig> <native-executable-role.sig> \
  </absolute/output/voboost-installer-<releaseIdentity>.dmg> <corresponding-source-directory>
```

Команда использует встроенный прямой ADB и закреплённое уведомление без внешнего executable ADB. Необязательный последний аргумент `arm64` или `x86_64` выбирает slice приложения для отдельного DMG. Она требует оба Mach-O slice у программы, точные `CFBundleDisplayName`/`CFBundleName` `Voboost Installer`, точный `CFBundleExecutable` `voboost-installer`, closure с проверенными подписью и hashes и fixtures для product, restore и native-executable roots, одинаково встроенных в оба slice. Команда ставит ad-hoc подпись на итоговый app с ресурсами, проверяет, что корневая CLI-ссылка ведёт к тем же байтам executable, создаёт DMG, подключает его read-only, повторяет полную проверку из подключённого образа и отключает его. При отсутствии или несовпадении любого входа output не сохраняется.

До подготовки пакета команда проверяет отдельный комплект исходников по точному product manifest. Этот комплект поставляется отдельным артефактом рядом с DMG. В корне образа находятся только `Voboost Installer.app` и CLI-ссылка; файлы `corresponding-source.tar.gz`, `corresponding-source.json` и `BUILD-MODIFIED.md` запрещены во входном приложении, подписанной closure, staging и подключённом образе. Команда упаковки не копирует исходники в DMG.

## Работа без сети

У desktop installer нет адреса для загрузки продукта, выбора канала, каталога выпусков и импорта локального манифеста. GUI и CLI используют только подписанный `voboost.json` и точную плоскую closure, упакованную для этого выпуска установщика. Наличие сети не может изменить выбранный выпуск или любой device artifact.

## Сборка без ключей

Обычная CI-задача установщика проверяет исходники и package constructors без закрытых ключей, координации выпуска, загрузки artifacts и права публикации.

Product repository собирает и подписывает полную closure из точных commits компонентов. Упаковка установщика получает эти неизменяемые подписанные байты, проверяет product manifest и inventory и не пересобирает и не подписывает Android-компоненты. Закрытые ключи не попадают во frontend или финальный пакет.

## Публикация

Публикацией владеет `voboost`, а не этот repository. Пакеты beta1 нельзя публиковать до локальной проверки на машине, доказательства чистого удаления, согласованного push исходников, сборки в CI, повторной проверки точных CI-пакетов на машине и отдельного решения пользователя.

## Исходные изображения и ресурсы интерфейса

Сохраняйте семь исходных PNG подключения в `src/assets/images/` для дальнейшего редактирования. Интерфейс импортирует только проверенные WebP из `src/content/index.ts`; PNG без импортов не копируются в результат сборки Vite. Для пяти иллюстраций используются пары светлых и тёмных WebP, сведённые на фактические фоны `webLightTheme`/`webDarkTheme`; у двух подлинных снимков системы также есть варианты для обеих тем. Неиспользуемый старый PNG из public остаётся удалённым.

Сжатие PNG без потерь должно сохранять размер холста, все декодированные RGBA-сэмплы, включая RGB прозрачных пикселей, а также цветовые метаданные, плотность и ориентацию. Отклоняйте результат оптимизатора, если он меняет эти свойства. PNG Android-фикстур относятся к тестовым APK репозитория agents и не являются ресурсами установщика. Их существующие тесты resource/Canvas проверяются отдельно. При сжатии PNG внутри ICNS сохраняйте все представления и остальные записи контейнера; после сборки проверяйте декодирование и пиксели через штатный `NSImage`. Тест `tests/connection-illustrations.test.ts` проверяет наличие исходных PNG и выбор WebP для интерфейса; `tests/macos-icon.test.ts` проверяет представления штатной иконки и её включение в пакет.

## Граница доказательств

Локальные проверки подтверждают исходники и структуру workflow. Отдельно проверяются реальная конфигурация CI, подпись, опубликованные байты, packaged GUI, подключённое устройство, перезагрузки, SELinux enforcing и автомобиль.
